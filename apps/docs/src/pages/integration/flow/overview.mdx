**The shell is instant. Slow parts wait.**

`@vincle/core` returns the page once every `await` has resolved: the slowest
query sets your time-to-first-byte. `@vincle/flow`, a separate package built on
the core, breaks that coupling.

You mark slow subtrees with `<Defer>`. The page shell ships
immediately. Fragments arrive later, each as soon as it resolves. No JavaScript
framework. No hydration. Just HTML in chunks.

## How it works

```tsx
import { Slot, Defer, renderToStream } from "@vincle/flow";
import { NativeAdapter } from "@vincle/flow/adapters";

declare function fetchComments(): Promise<{ text: string }[]>;

async function Comments() {
  const items = await fetchComments();
  return (
    <ul>
      {items.map((c) => (
        <li>{c.text}</li>
      ))}
    </ul>
  );
}

// <Slot> declares the placeholder with fallback content in the shell.
// <Defer> pushes the real content, which replaces it when resolved.
function Page() {
  return (
    <html>
      <body>
        <h1>My page</h1>
        <Slot name="comments">
          <p>Loading comments…</p>
        </Slot>
        <Defer target="comments">{() => <Comments />}</Defer>
      </body>
    </html>
  );
}

// The shell is sent immediately; deferred fragments stream
// in as they resolve. NativeAdapter injects a small polyfill.
const stream = renderToStream(() => <Page />, NativeAdapter);
```

- Everything outside a `<Defer>` belongs to the shell. An `await` there delays
  the shell, so keep slow work inside a `<Defer>`.
- Each `<Defer>` runs on its own, and patches are sent in the order they finish,
  not the order they appear in the page.
- A `<Defer>` nested in another one is sent after its parent.

## `<Defer>` and `<Slot>`

- **`<Defer>`**: defers content into a placeholder. It renders its own
  placeholder, so it is self-sufficient
- **`<Slot>`**: a named placeholder, filled by a `<Defer>` that renders
  elsewhere in the tree: typically a layout reserving a spot, filled by a page
  component that cannot reach into that layout

`Defer` renders `fallback` (empty when omitted) until the content is ready, and
its first patch replaces that fallback. Pass a factory to receive an
`AbortSignal`: it fires when the client disconnects or the fragment's `timeout`
elapses, so you can forward it to cancelable work (e.g. `fetch(url, { signal })`).

```tsx
<Defer fallback={<p>Loading dashboard…</p>} timeout={5000}>
  {(signal) => <HeavyDashboard signal={signal} />}
</Defer>
```

| Prop       | Applies to | Meaning                                                             |
| ---------- | ---------- | ------------------------------------------------------------------- |
| `name`     | `Slot`     | id of the placeholder (required)                                    |
| `target`   | `Defer`    | optional placeholder id; generated automatically when omitted       |
| `fallback` | `Defer`    | placeholder content shown in the shell, replaced by the first patch |
| `merge`    | `Defer`    | how content applies to its target (default `"replace"`)             |
| `timeout`  | `Defer`    | per-fragment render timeout in ms                                   |
| `onError`  | `Defer`    | per-fragment error handler, overriding the renderer's one           |

`merge` is one of `"replace"`, `"update"`, `"append"`, `"prepend"`, `"before"`,
`"after"` or `"morph"` (diffed in place, keeps focus and form state). An adapter
rejects a merge type it does not support. Without `onError`, a failed fragment
is logged and the placeholder keeps its fallback.

`Defer` children are a value, or a factory returning one: a `JSX.Element` or
`string` renders one patch; an `AsyncIterable<JSX.Element>` streams one patch
per yielded item, until the iterable ends or the client disconnects.

```tsx
import { Defer } from "@vincle/flow";

declare function fetchRows(page: number): Promise<{ id: number; name: string }[]>;

<Defer target="feed" merge="append">
  {async function* () {
    let page = 1;
    while (true) {
      const rows = await fetchRows(page++);
      if (rows.length === 0) break;
      for (const row of rows) {
        yield <tr key={row.id}>{row.name}</tr>;
      }
    }
  }}
</Defer>;
```

## Two rendering modes

- **Streaming**: fragments arrive in the same HTTP response after the shell,
  via `renderToStream()` or `serve()`. One connection, progressive delivery.
- **Static generation**: fragments are emitted as separate HTML files at build
  time via `renderToStatic()`. The browser fetches them on load.

Both, plus adapter choice and HTTP integration, are covered in
[Recipes](/integration/flow/recipes), and the full signatures in the
[Flow API reference](/api/flow/reference).

For a quick answer, see [Can I use Vincle for streaming HTML?](/guide/faq#can-i-use-vincle-for-streaming-html).
