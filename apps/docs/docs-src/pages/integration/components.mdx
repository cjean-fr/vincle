# Components

Two primitives handle declaring a placeholder and deferring content into it —
plus a third for fetching a fragment from a separate URL entirely:

- **`<Template>`** — defers content into a placeholder, sync or lazy; renders
  its own placeholder, so it's self-sufficient
- **`<Slot>`** — a named hole, standing in for a `<Template>` that renders
  elsewhere in the tree
- **`<Include>`** — client-side fetch placeholder

## `<Template>` — defer content (sync or lazy)

Registers content — plain JSX or a lazy factory — under a `target` id, and
renders a placeholder in its own place showing `fallback` until that content
is ready. No `<Slot>` required: for the common case, placeholder and content
live together, in the same spot. **Unified** — one component for both
synchronous and deferred content. The behaviour depends on `children`:

| `children` type | `fallback` | Behaviour                                        |
| --------------- | ---------- | ------------------------------------------------ |
| Plain JSX       | —          | Content registered; placeholder rendered (empty) |
| Plain JSX       | provided   | Content registered; placeholder shows `fallback` |
| `(signal) => …` | —          | Lazy content; placeholder rendered (empty)       |
| `(signal) => …` | provided   | Lazy content; placeholder shows `fallback`       |

### Sync — push content

`children` is deferred automatically — plain JSX works:

```tsx
<Template target="page">
  <h1>Hello</h1>
</Template>
```

### Lazy — with placeholder

Declares a deferred region with a placeholder in the shell. The `fallback` prop
defines the content shown immediately:

```tsx
import { Template } from "@vincle/flow";

<Template target="dashboard" fallback={<p>Loading dashboard…</p>}>
  <HeavyDashboard />
</Template>;
```

Pass a factory when you need the `AbortSignal` — it fires when the client
disconnects, or when the fragment's `timeout` elapses. Forward it to your own
cancelable work (e.g. `fetch(url, { signal })`) so that work stops early:

```tsx
<Template target="dashboard" fallback={<p>Loading dashboard…</p>}>
  {(signal) => <HeavyDashboard signal={signal} />}
</Template>
```

The signal firing doesn't cut the render itself short — Vincle still renders
whatever the factory returns. What it does control is the _outcome_: if the
signal has already fired by the time the render finishes, the result is
discarded and routed to `onError` instead of being emitted.

### Merge types

`merge` controls how the content applies to the target element:

| `merge`     | Effect                                    |
| ----------- | ----------------------------------------- |
| `"replace"` | Target element is replaced (default)      |
| `"append"`  | Content inserted as last child of target  |
| `"prepend"` | Content inserted as first child of target |
| `"before"`  | Content inserted as previous sibling      |
| `"after"`   | Content inserted as next sibling          |

Not every adapter supports all merge types — an unsupported merge is rejected
at registration with a clear error.

## `<Slot>` — named insertion point

Declares a named hole in the shell, standing in for a `<Template>` that
renders **elsewhere** in the tree — typically a layout reserving a spot by
name, filled later by a page-specific component that has no other way to
reach into that layout. Its `children` are rendered **immediately** as
placeholder content — visible until the matching `<Template>` patches them.
An empty slot renders an empty placeholder.

```tsx
import { Slot } from "@vincle/flow";

<Slot name="comments">
  <p>Loading comments…</p>
</Slot>;
```

A `Slot` registers nothing in the pending store — it is purely a passive
hole. `name` is **required**.

If the placeholder and the deferred content are declared in the same spot,
skip `Slot` — `Template` alone, with its own `fallback`, is simpler and does
the same job (see above). Reach for `Slot` only for the decoupled case.

**Ordering matters when pairing them.** Every adapter renders a placeholder
as an element (or marker) carrying the target's id, and every adapter's
patch resolves to the _first_ match in the document — the same rule HTML
`id` uniqueness and `getElementById` already impose. So `<Slot>` must come
before the matching `<Template>`, and that `<Template>` should skip its own
`fallback` — passing one renders a second, dead placeholder with the same id
right next to `Slot`'s live one:

```tsx
// Layout.tsx — reserves the spot; has no idea what fills it
<Slot name="comments">
  <p>Loading comments…</p>
</Slot>

// CommentsPage.tsx — fills it; has no idea where it renders
<Template target="comments">
  <LiveComments />
</Template>
```

## Return types

`Template` children accept the full `TemplateContent` type — a renderable JSX
node, a string, or an async iterable, each optionally produced by a factory
that receives the `AbortSignal`:

| Children / return type                                | Behaviour                                                |
| ----------------------------------------------------- | -------------------------------------------------------- |
| `JSX.Element`                                         | One-shot patch — renders once and resolves               |
| `string`                                              | Rendered as text — one-shot patch                        |
| `(signal: AbortSignal) => JSX.Element`                | **Cancellable** — receives the signal, one-shot patch    |
| `AsyncIterable<JSX.Element>`                          | A **stream** — one patch per item, as each item resolves |
| `(signal: AbortSignal) => AsyncIterable<JSX.Element>` | **Cancellable stream** — one patch per item              |

The runtime unwraps `AsyncIterable` automatically inside the factory — you
never need to call `.then()` or `for await` yourself.

## Common props

| Prop       | Applies to | Meaning                                                      |
| ---------- | ---------- | ------------------------------------------------------------ |
| `name`     | `Slot`     | id of the placeholder (required)                             |
| `target`   | `Template` | id the placeholder (and its later patch) is registered under |
| `fallback` | `Template` | placeholder content shown in the shell (lazy only)           |
| `merge`    | `Template` | how content applies to its target (default `"replace"`)      |
| `timeout`  | `Template` | per-fragment render timeout in ms                            |
| `onError`  | `Template` | per-fragment error handler, overriding the renderer's one    |
| `src`      | `Include`  | URL the browser fetches for the fragment content             |
