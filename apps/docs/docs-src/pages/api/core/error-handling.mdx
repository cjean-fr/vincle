# Error handling

Errors throw or reject bare. There is no component-level boundary that catches
them mid-tree.

## Rationale

Server-side rendering is fundamentally different from client-side React, and a
boundary component has little to catch:

- **No recovery after output** — once HTML is sent, a boundary can't
  retroactively replace it. The server's only choice is what to send next.
- **SSR errors are exceptional** — a server error usually means a 500, not
  a graceful partial fallback.
- **Streaming recovery is per-fragment** — `@vincle/flow` provides `onError`
  for the streaming case, which is more granular than a boundary.

## Top-level errors

Wrap `renderToString` in try/catch for a global fallback:

```tsx
import { renderToString } from "@vincle/core";

try {
  const html = await renderToString(<Page />);
  // send html to client
} catch (error) {
  console.error("Page render failed:", error);
  // send a 500 or fallback page
}
```

An `Error` thrown by a component is annotated with that component's name,
once — the innermost one, not the whole chain:

```tsx
function Profile() {
  throw new Error("not found");
}

try {
  await renderToString(<Profile />);
} catch (e) {
  // e.message === "[Profile] not found"
}
```

A thrown value that isn't an `Error` (a string, a plain object) is never
wrapped — `catch` sees exactly what was thrown.

## Message format

Every error vincle raises is prefixed and self-contained — it says **where** it
came from, **what** went wrong (naming the offending value), **why**, and **how
to fix it**:

```
[vincle/<package>] <api or component>: <what happened>. <why>. <how to fix it>
```

Real examples:

```
[vincle/core] useContext("app:theme"): the value was never set in the current scope. Set it above the reader with setContext(key, value) inside the same withScope()…
[vincle/flow] <Template target="hero">: merge="prepend" is not supported by this adapter — it supports: replace, append. Pick one of those, or use an adapter that supports "prepend".
[vincle/vite-plugin] Vite entry "src/logo.sv" not found in manifest. Did you mean "src/logo.svg"? The manifest only lists files Vite bundles…
```

The prefix is stable and greppable (`[vincle/core]`, `[vincle/flow]`,
`[vincle/vite-plugin]`, `[vincle/vite-plugin-precompile]`), so you can filter
vincle errors out of a log or match them in CI.

Config errors fail **fast**, at the entry point that receives the config —
before a single byte is rendered or a build starts:

- `@vincle/flow`: `renderToStream`, `renderToFlowEvents`, `renderToStatic`,
  `renderFragment`, `createAdapter`, and the flow config (`mode`, `adapter`,
  `generatePath`, `idPrefix`) are all validated at call time, as are
  `defaultTimeout`, `onError`, `signal`, and per-fragment `timeout`.
- `@vincle/vite-plugin`: `setVite` checks `base`; `loadViteManifest` names the
  file when it is unreadable, not JSON, or not a manifest.
- `@vincle/vite-plugin-precompile`: `runtimeSource` and `secure` are checked
  when the plugin is created; build-time probes name the failing module and the
  fix.

## Per-fragment errors (streaming)

For streaming renders, `@vincle/flow` provides `onError` on the
`serve()` options and individual `<Template>`s:

```tsx
serve(req, () => <Page />, NativeAdapter, {
  onError: (error, { id, kind }) => {
    console.error(`Fragment ${id} failed:`, error);
    return <p>This section failed to load.</p>;
  },
});
```

See the [Flow streaming API](/api/flow/renderToStream) for details.
