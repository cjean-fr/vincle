# Error handling

Errors throw or reject bare. There is no component-level boundary that catches
them mid-tree.

## Rationale

Server-side rendering is fundamentally different from client-side React, and a
boundary component has little to catch:

- **No recovery after output**: once HTML is sent, a boundary can't
  retroactively replace it. The server's only choice is what to send next.
- **SSR errors are exceptional**: a server error usually means a 500, not
  a graceful partial fallback.
- **Streaming recovery is per-fragment**: `@vincle/flow` provides `onError`
  for the streaming case, which is more granular than a boundary.

## Top-level errors

Wrap `renderToString` in try/catch for a global fallback:

```tsx
import { renderToString } from "@vincle/core";

try {
  const html = await renderToString(<Page />);
  // send html to client
} catch (error) {
  console.error("Page render failed:", error);
  // send a 500 or fallback page
}
```

The `try` block catches errors both while `<Page />` is constructed and while
`renderToString` walks it. Attaching `.catch()` to the returned promise would
not catch an error thrown before the call begins.

An `Error` thrown by a component is annotated with that component's name,
once: the innermost one, not the whole chain:

```tsx
function Profile() {
  throw new Error("not found");
}

try {
  await renderToString(<Profile />);
} catch (e) {
  // e.message === "[Profile] not found"
}
```

A thrown value that isn't an `Error` (a string, a plain object) is never
wrapped: `catch` sees exactly what was thrown.

## Message format

Every error vincle raises is prefixed and self-contained. It says **where** it
came from, **what** went wrong (naming the offending value), **why**, and **how
to fix it**:

```
[vincle/<package>] <api or component>: <what happened>. <why>. <how to fix it>
```

Real examples:

```
[vincle/core] Scope.get("app:theme"): the value was never set in the current scope. Set it above the reader with Scope.set(key, value) inside the same Scope.with()…
[vincle/flow] <Defer target="hero">: merge="prepend" is not supported by this adapter: it supports: replace, append. Pick one of those, or use an adapter that supports "prepend".
[vincle/vite-plugin] Vite entry "src/logo.sv" not found in manifest. Did you mean "src/logo.svg"? The manifest only lists files Vite bundles…
```

Error messages use the current `Scope.*` names, so a message names the exact
call to fix.

The prefix is stable and greppable (`[vincle/core]`, `[vincle/flow]`,
`[vincle/vite-plugin]`, `[vincle/precompile]`), so you can filter
vincle errors out of a log or match them in CI. To tell them apart _in code_,
read `error.code` rather than the message: see below.

## Error codes

Every error vincle throws carries a `code`, following Node's
convention. `TypeError` is also what a component throws when it has a bug of its
own, so the type alone cannot say whether the refusal came from vincle:

```ts
try {
  html = await renderToString(<Page />);
} catch (error) {
  if (error.code === "ERR_VINCLE_VOID_CHILDREN") {
    // the markup is wrong, not the data
  }
}
```

| Code                         | Raised when                                                       |
| ---------------------------- | ----------------------------------------------------------------- |
| `ERR_VINCLE_INVALID_TAG`     | a tag name that cannot be written as HTML                         |
| `ERR_VINCLE_VOID_CHILDREN`   | content inside a void element (`<br>`, `<img>`, …)                |
| `ERR_VINCLE_DANGEROUS_HTML`  | `dangerouslySetInnerHTML.__html` is not a string                  |
| `ERR_VINCLE_FUNCTION_ATTR`   | a function passed as an attribute value                           |
| `ERR_VINCLE_VNODE_AS_TEXT`   | a component interpolated where text belongs                       |
| `ERR_VINCLE_SCOPE_COLLISION` | overlapping renders or `Scope.with()` with no `AsyncLocalStorage` |
| `ERR_VINCLE_NO_STORE`        | the Scope store was read before `Scope.with()` ran                |
| `ERR_VINCLE_NO_SCOPE`        | a Scope call outside any `Scope.with()`                           |
| `ERR_VINCLE_CONTEXT_KEY`     | `Scope.key()` given something other than a non-empty string       |
| `ERR_VINCLE_CONTEXT_LIMIT`   | more distinct context keys than the table holds                   |
| `ERR_VINCLE_CONTEXT_UNSET`   | `Scope.get()` read a value never set in scope                     |

The first three are `TypeError`s: an argument that is not what it has to be.
Every other code in this page, here and below, is a plain `Error`.

### `@vincle/flow`

| Code                                | Raised when                                          |
| ----------------------------------- | ---------------------------------------------------- |
| `ERR_VINCLE_FLOW_CONFIG`            | an option rejected at the entry point that took it   |
| `ERR_VINCLE_FLOW_NO_ADAPTER`        | a placeholder or fragment with no adapter configured |
| `ERR_VINCLE_FLOW_MERGE_UNSUPPORTED` | a `merge` the adapter cannot express                 |
| `ERR_VINCLE_FLOW_FRAGMENT_ID`       | a fragment id that cannot be a DOM id or URL segment |
| `ERR_VINCLE_FLOW_NO_FRAGMENT`       | `renderFragment` produced nothing for that id        |
| `ERR_VINCLE_FLOW_NO_STREAMING`      | `renderToStream` given an adapter that cannot stream |
| `ERR_VINCLE_FLOW_FORBIDDEN_SCHEME`  | an `<Include src>` scheme outside the whitelist      |

### `@vincle/vite-plugin` and `@vincle/precompile`

| Code                             | Raised when                                                |
| -------------------------------- | ---------------------------------------------------------- |
| `ERR_VINCLE_VITE_MANIFEST_READ`  | the Vite manifest could not be read                        |
| `ERR_VINCLE_VITE_MANIFEST_PARSE` | the manifest is not JSON                                   |
| `ERR_VINCLE_VITE_MANIFEST_SHAPE` | the file parsed but is not a manifest                      |
| `ERR_VINCLE_VITE_CONFIG`         | `setVite` given an option it cannot use                    |
| `ERR_VINCLE_VITE_MISSING_ENTRY`  | an entry the manifest does not list                        |
| `ERR_VINCLE_PRECOMPILE_CONFIG`   | `runtimeSource` is not a module specifier                  |
| `ERR_VINCLE_PRECOMPILE_HELPER`   | a runtime helper answered a shape the transform cannot use |
| `ERR_VINCLE_PRECOMPILE_INTERNAL` | an invariant of the transform broke: a bug to report       |

The codes are not exported: compare against the string, as you would an
`ENOENT`. The set may grow; an existing code will not be renamed or reused.

Config errors fail **fast**, at the entry point that receives the config,
before a single byte is rendered or a build starts:

- `@vincle/flow`: `renderToStream`, `renderToFlowEvents`, `renderToStatic`,
  `renderFragment`, `createAdapter`, and the flow config (`mode`, `adapter`,
  `generatePath`, `idPrefix`) are all validated at call time, as are
  `defaultTimeout`, `onError`, `signal`, and per-fragment `timeout`.
- `@vincle/vite-plugin`: `setVite` checks `base`; `loadViteManifest` names the
  file when it is unreadable, not JSON, or not a manifest.
- `@vincle/precompile`: `runtimeSource` is checked when the plugin is
  created; a runtime declaring the `"vincle"` precompile dialect without the
  helpers to back it fails the build, and an unreadable runtime module warns and
  falls back to Deno's output.

## Per-fragment errors (streaming)

For streaming renders, `@vincle/flow` provides `onError` on the
`serve()` options and individual `<Defer>`s:

```tsx
serve(req, () => <Page />, NativeAdapter, {
  onError: (error, { id, kind }) => {
    console.error(`Fragment ${id} failed:`, error);
    return <p>This section failed to load.</p>;
  },
});
```

See the [Flow streaming API](/api/flow/renderToStream) for details.
