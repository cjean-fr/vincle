# Your views in JSX. Your app in HTML.

Vincle lets you compose typed JSX views in your existing server.
Start with one component, render it to HTML, and return it from a route.

## Compose a view

With `@vincle/core`, components are functions, props are TypeScript values, and
the result is an HTML string. The renderer adds no browser runtime.

```tsx
import { renderToString } from "@vincle/core";

function App({ name }: { name: string }) {
  return <h1>Hello, {name}!</h1>;
}

const page = <App name="world" />;
const html = await renderToString(page);
```

```html
<h1>Hello, world!</h1>
```

Set up [the package](/guide/getting-started/installation) and
[JSX in TypeScript](/guide/getting-started/typescript-setup), then connect
the rendered HTML to your server's response API. You keep your routing,
data access, and deployment setup.

## Load data in your components

A component can be async. The renderer awaits its result before producing
the final HTML.

```tsx
import { renderToString } from "@vincle/core";

declare const db: {
  users: {
    findById(id: string): Promise<{ name: string; email: string }>;
  };
};

async function UserCard({ id }: { id: string }) {
  const user = await db.users.findById(id);
  return (
    <div class="card">
      <h2>{user.name}</h2>
      <p>{user.email}</p>
    </div>
  );
}

const html = await renderToString(<UserCard id="42" />);
```

Components execute in document order. Async support does not automatically
parallelize sibling components: a complete string response waits for the tree.

## Let slower parts arrive later

Add `@vincle/flow` when a page should appear before all its data is ready.
Wrap a slow component in `Defer`, provide a fallback, and use the streaming
renderer to send the surrounding page before its deferred fragments.

[Follow a view from a route to streaming HTML](/guide/views).

Flow's adapters determine how fragments update the page, including integration
with HTMX and Turbo. Browser updates use the selected adapter's client mechanism;
see [Adapters](/integration/adapters) for setup and capabilities.

## What the core provides

- **Typed components and attributes** — check props and HTML attributes with TypeScript.
- **Tree context and scopes** — a React-style `createContext` passes a value to
  a subtree (`<Context.Provider>` + `useContext`); `Scope` holds mutable
  per-request state. See the [Context & Scope API](/api/core/scope).
- **Default escaping** — text and attributes are escaped, and dangerous URL schemes
  are filtered. See the [security model](/guide/security) for context-specific
  rules and trusted HTML escape hatches.
- **A self-contained package** — the core has no runtime dependencies and includes
  its element types.
- **HTML output** — send a response, write a static page, or pass a template to an
  email provider. Email client compatibility remains part of your template design.

Vincle does not hydrate components into a reactive client application.
Use it when your views produce HTML and add client-side behavior through
your chosen tools.
